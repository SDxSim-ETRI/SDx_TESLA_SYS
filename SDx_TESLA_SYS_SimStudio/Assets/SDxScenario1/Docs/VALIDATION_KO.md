# 상황1 검증 기록

## 실행한 검사

사용자가 제공한 MuJoCo 3.16.0 라이브러리로 동적 물리 검사를 수행했습니다.
모델은 업로드된 MainScene의 배치·충돌 자산과 이후 스크린샷의 로봇/책 위치 변경을 반영하여 재구성했습니다.
Unity가 생성한 최종 런타임 XML을 추출한 것은 아닙니다.

최종 조정된 경로와 관절 자세로 **2회** 성공했습니다. 두 번째 실험 전에는 이전 종료/교란 상태에서
리셋을 적용하여 qpos 초기 복원, qvel=0, ctrl=0을 확인했습니다.
실험은 전체 적분 상태를 저장·복원하는 구간 실행 방식으로 이어서 수행했습니다.

| 항목 | 측정 결과 |
|---|---|
| 물리 시간 간격 | 0.001초 |
| 성공한 최종 반복 검사 | 2회 |
| 책의 최종 Unity 좌표 | (5.2289495, 0.9243414, -4.5000980) m |
| 목표 중심과의 거리 | 1.055 mm |
| 책의 최종 방향 오차 | 0.0380도 |
| 마지막 책 상태 | 그리퍼를 놓고 팔을 복귀한 뒤 선반 위에서 정지 |
| 동작 후 정지 관찰 | 5초의 시뮬레이션 시간 |
| 접촉 경로 표본 검사 | 0.2초 간격, 744개 상태 |
| 위 표본에서 의도하지 않은 로봇/대상 책 접촉 | 0건 |

파지 중에는 자유 관절을 가진 책과 손가락의 접촉력을 사용했습니다.
책-손목 고정 제약, Parenting, 지속적인 위치 강제 설정으로 성공시킨 실험은 아닙니다.

경로 조정 과정에서는 기존 RoomWall의 충돌 영역을 피하도록 통로 경유점을 조정했고,
삽입 시 다른 팔과 충돌하지 않도록 역기구학의 팔꿈치 기준 자세를 지정했습니다.
공개한 `native_run_1.json`, `native_run_2.json`은 이 조정이 끝난 최종 반복 실험의 기록입니다.

## 코드/설치 검사

C# 괄호 균형·파일 의존 구조, 고정 관절 배열의 시험값 일치, 모델을 중복 stepping하지 않는 구조,
설치 프로그램의 최초 설치·덮어쓰기 및 .meta 보존 등을 검사했습니다.
세부 목록은 `Validation/static_checks.json`에 있습니다.

이 검사는 **C# 컴파일 검사와 같지 않습니다.**

## 수행하지 못한 검사

- Unity Editor에서 실제 C# 컴파일
- 사용자 PC의 최신 MainScene 통합 Play
- 실제 GUI 키보드 입력부터 완료까지의 Unity 화면 기록
- 전체 실행의 매 1ms마다 모든 접촉에 대한 별도 사후 감사
- 실제 로봇 하드웨어 시험

따라서 네이티브 재구성 모델의 성공을 사용자 Unity Scene의 실행 성공으로 바꾸어 표현하지 않습니다.
Unity 적용 후 Console과 화면 결과를 확인해야 합니다.
